| `paraphrase` | `golden_questions.json` | Differently-worded real questions still classify to the correct intent and produce correct deterministic answers (keyword+fuzzy path). |

| `multi_intent` | `bench_extractor_scenarios.json` | A single question with 2+ intents (e.g. "battery voltage and cctv status for X") produces one combined reply with visibly separated sections. |
| `injection` | `bench_safety_corpus.json` | 22-attack corpus (ignore-instructions, system-prompt extraction, persona switches, DAN/developer mode, delimiter smuggling, rule overrides) — every one must be blocked by the pre-LLM safety gate. |

| `false_positive` | `bench_safety_corpus.json` | Legitimate questions that share vocabulary with attacks ("how do I ignore a false alarm", bare branch codes) — every one must pass through clean. |

## How to extend it

- **Add a paraphrase/entity/knowledge scenario:** append an entry to `golden_questions.json`
  (`question`, `intent`, `category`, optional `matchedBranch`, `contains` fragments). No
  Java code needed — `TestBenchRunner` picks it up automatically.
- **Add a multi-intent/extractor scenario:** append to `bench_extractor_scenarios.json`
  and a matching recorded extraction to `extractor_recordings.json`.
- **Add a safety probe:** append the string to the relevant array in
  `bench_safety_corpus.json` — used by both `SafetyGateServiceTest` (unit-level) and the
  bench scorecard (release-gate level), so there's one source of truth.

## Known gaps

- `entity_resolution` corpus is 7 real-world typo pairs — enough to validate threshold
  direction (see `phase5_calibration_and_handoff.md`), thin for detecting subtle
  regressions. Grow it as new typo patterns are observed in production.
- No live extractor calibration data yet — `extractor.agreement` metrics require shadow
  mode running against real traffic (not yet deployed). See deployment guide.
- Bench covers deterministic and replay-extractor paths only; it does not exercise the
  live `LlmIntentExtractor` against the real OpenAI API (that's `LlmIntentExtractorTest`,
  mocked, plus an opt-in live smoke test path described in the Phase 2 plan but not built —
  intentionally deferred to avoid non-deterministic CI runs).
